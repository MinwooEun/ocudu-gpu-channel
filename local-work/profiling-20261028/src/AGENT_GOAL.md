# Mission

**This file defines the long-term mission. It is agent-immutable unless the user explicitly instructs an amendment. Routine tasks and inferred preferences do not amend it.**

## Statement

Develop and maintain a real-time GPU-accelerated wireless-channel emulator for live OCUDU and srsRAN stacks, together with its directly supporting code, experiments and documentation.

## Scope

- Detailed scope is not yet specified for this reset. The mission statement is the durable scope; individual task instructions do not become persistent scope without an explicit amendment.

## Non-Goals

- Fallbacks, guards, silent substitutions or defensive special cases that make a result look better than the mechanism earned. Measure and report misses rather than covering them.
- Robustness, generality, scaffolding or polish that no result depends on. Effort belongs to the substance of the work.
- Work outside the mission statement. Request user direction rather than inferring a broader mission.

## Success Criteria

- Not yet specified for this reset. Do not infer durable completion criteria from task progress; obtain the user's explicit criteria before recording them.

## Constraints

- Understanding is a precondition for work. If the user does not understand a result, mechanism, artifact or plan, stop work on it and explain it plainly. Resume only when the user says it is clear; improve the explanation rather than merely rewording it.
- Assess understanding proactively. Repeated questions, one-word replies, requests for brevity, challenges to introduced terms or visible frustration trigger the explanation stop condition. Silence is not comprehension; a misunderstanding is an explanation defect, never a user defect.
- Keep one mechanism per component, in plain sight. Do not hide misses with fallbacks, guards, substitutions or defensive special cases. Measure the mechanism's actual result and spend effort on work the result depends on.
- Use one vocabulary across documentation, code and conversation, defined in the existing “Key terms” glossary in `docs/index.html`. Define terms before introducing them, avoid synonyms for the same concept, and propagate renames across surfaces. An unexplained term triggers the explanation stop condition.
- Keep only mission-defining constraints here. Workflow, style, formatting, validation habits and operating routines belong in `AGENT_HARNESS.md`.

**Amendment procedure.** Change a section only on explicit user instruction identifying the section and replacement content. Record the amendment in `AGENT_PROGRESS.md` as one brief bullet noting that the user amended the mission; do not infer amendments from new tasks or shifts in emphasis.
