Why

The emulator's CUDA backend was written for a discrete GPU such as the RTX 5090. Every slot (1 ms, 23,040 samples, 184 KB per direction), it gathered the IQ into a pinned buffer, sent it to the GPU with cudaMemcpyAsync, and copied the result back. On GB10 the CPU and GPU share one DRAM, but the code still asked for the copies, so they still happened.

That is why the 09-26 comparison showed the same emulator time on both platforms (44.8 vs 43.6 µs). GB10 copied a little faster but computed about 2× slower. The goal here was a separate path, used only on integrated GPUs, that drops those copies. The hard requirement was output that is bit-identical to the copy path.

What was done

  1. A knob: runtime.cuda_host_memory: copy | zero_copy | auto. The default is copy, which is the old behavior. auto selects zero-copy only on a device that reports cudaDevAttrIntegrated. 6fab580
  2. Mapped input and output buffers. They are allocated with cudaHostAllocMapped, and the GPU reads and writes that memory directly. The per-slot H2D/D2H IQ copies are gone. 6fab580
  3. Direct output. When the device can access pageable memory, the kernels write straight into the caller's (the broker's) output row. That removes the last CPU copy on the output side. 6fab580
  4. Mapped metadata was tried and dropped. It saves 1.5 µs of H2D, but every GPU thread then re-reads the step data from host memory, and the kernel gets 8 µs slower. It was measured and left out of the default. 6fab580
  5. Direct input. The channel kernels used to find source IQ in one packed buffer. They now use a per-source pointer table (DeviceSourceTable, a __grid_constant__ kernel parameter holding up to 128 entries). The GPU reads the broker's input windows in place. The CPU no longer packs many UEs' IQ into one buffer, and the H2D of that buffer is gone too. This was the largest remaining cost with many users. 0a6f281
  6. Broker ring fix. IqRing::push/read copied one sample at a time with a modulo per sample. They now do at most two block copies around the wrap. Behavior is unchanged, and the CPU backend benefits too. 0a6f281
  7. Instrumentation. ProcessorTimings gains host_prep_us, host_out_us, call_us, and zero_copy. The bench prints them, prints cuda_zero_copy (the mode that actually ran), and has --per-node. This is how CPU input packing was identified as the remaining bottleneck.
  8. Verification. Copy vs 10 zero-copy combinations are compared bit for bit over 4 slots. There is also a 3-UE fan-in case and a randomized ring test against a reference model. Three negative controls (deliberately broken code) all fail as they should.
  9. Live runner. OCUDU_NATIVE_CHANNEL_BUILD overrides the broker build directory, so the gate can run from a second source tree.
  10. Docs. README documents the knob and the new bench output. ZERO_COPY_MILESTONES.md records each step (Z0–Z8) with its plan, evidence, and log locations.

ConfigurationcopyZ5Z8Z8 cutCPU input packing: copy → Z8
  • Bandwidth: Every copy that was removed scales with bytes, so the cut reaches −74% at 122.88 MS/s (100 MHz class).
  • Users: The gNB sums N UEs' uplinks in one call. With copy, the CPU packing of N UEs' IQ took 524 µs at N = 64, more than half the call. Z8 removes it, and N = 64 takes 177 µs.
  • Slot budget (30 kHz, 500 µs): N64 (714 µs) and N16 at 92 MS/s (646 µs) were still over budget at Z5. They now take 177 and 145 µs.
  • TDL-A (23 taps) is dominated by GPU compute, so it improves only 19%. Removing copies cannot shorten the compute itself.

Limits and open items

  • The default is still copy. Jetson Orin (Z6) is not validated yet, so switching the default to auto is on hold. For now, a config must set cuda_host_memory: auto or zero_copy to use this path.
  • Do not use it on a discrete GPU. On the 5090 every access crosses PCIe, and TDL-A gets 43× slower. auto selects copy there.
  • Three observations with unverified causes. Why mapped-memory kernels cost more than pageable reads. Why the ring stages take 5–10 µs longer under zero-copy than under copy. Why live kernel and H2D times are 5–7 µs above the bench. None of these were checked with nsys or ncu.
  • MIMO output (2 or more rows) does not use direct output. A node with more than 128 sources falls back to packed input.
  • Next candidates. Separate the live-vs-bench gap, remove the step-metadata H2D (3–8 µs), and add a path that bypasses the rings (a broker restructure).
