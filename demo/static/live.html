What are these numbers?

Everything here is reported by a REAL 5G stack — srsUE attached to an OCUDU gNB through an Open5GS core — whose radio waveform passes through the GPU channel emulator instead of antennas. RSRP is the downlink reference-signal power the UE measures (drops exactly when the emulated channel attenuates), DL SNR is the UE's demodulation SNR, DL/UL bitrate is actual MAC-layer user traffic, and ping RTT is a live ICMP round-trip from the UE's network namespace through the whole stack — radio, gNB, core — and back. If the channel knob below moves these numbers, the entire 5G protocol stack felt it.

What does this slider do?

It sends a scalar path_loss_db message to the emulator's ZMQ control plane; the CUDA kernel applies the attenuation at the next slot boundary (<1 ms granularity, no restart). 12 dB visibly drops RSRP and raises RTT; ~25 dB and the UE starts losing the link — that is a real radio-link failure, induced in software. The telemetry line above is the emulator's own report of what it is currently applying, so you can compare "commanded" against "measured by the UE".

How to read the three time-series

DL SNR reacts within one metrics period (0.5 s) of a channel change — it is the most direct radio-quality view. DL bitrate is bursty because it tracks actual scheduled traffic, not channel quality alone. Ping RTT rises before the link breaks: as SNR falls, HARQ retransmissions add milliseconds — protocol-level stress made visible.
