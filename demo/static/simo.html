Per-port RX power vs the declared steering pattern re-steering… bars = measured; ticks = analytic |ar|²

One UE TX port into four gNB RX ports through a declared rank-1 vector a. The channel is deterministic (single 0 dB tap, no fading), so each bar sits exactly on |ar|². Re-steering re-renders the topology and restarts the broker — the ~2 s gap is the restart drill.
What am I looking at?

This is receive beamforming geometry made visible. One transmitter, four receive antennas, and a declared rank-1 steering vector a: each antenna hears the same signal weighted by its own coefficient, so the four bars ARE the vector, drawn as |ar|². Green bars = measured power; orange ticks = the declared values — they match to the third decimal because this channel is deterministic (no fading), which is exactly how you verify a MIMO implementation before adding randomness. Pressing the other steering button points the vector the other way and the bars mirror — the same reordering a real system's beam management would produce as a user walks across a cell. This 1×4 rank-1 declaration is the repo's rank-1 MISO/SIMO contribution.
